# TacticalTablet: компактный тактический терминал

Спецификация редизайна для Minecraft Forge 1.20.1. Координаты и размеры ниже заданы в **логических GUI-пикселях**; в Figma 1 px = 1 GUI px. Никаких дробных координат, полупиксельных линий, размытия или масштабирования текстур с линейной фильтрацией.

Figma: https://www.figma.com/design/PmylLqutDUVcnF7sIgh3aL

## Источники данных и границы

- Состав страниц, действие по нажатию и геометрия текущего планшета: `TabletScreen`, `BaseClassPanel`, `ScrollableGridLayout`, `TabletNavigationRail`.
- Доступность класса и прокачки: `ClassProgressionPresentation`, `TabletPacket`, `ClassDefinitions`, `ShopClassCatalog`, `CosmeticCatalog`.
- Профиль: только монеты, победы, матчи, убийства, смерти, KDA и процент карьерного прогресса из `TabletStatePacket` / `TabletProfileView`.
- Кланы: только поля `ClanListPacket.ClanEntry` и действия текущих C2S-пакетов. Имя 3–24 символа, тег 1–4, максимум 8 кланов, 10 участников, 64 заявки в клан и 5 одновременных заявок игрока; сервер также ограничивает частоту подачи заявок. Создание 1000 личных монет. Изменение цвета стоит 10 клановых монет. Палитра — восемь цветов из `ClanConstants.ALLOWED_COLORS`; занятые цвета и текущий цвет недоступны.
- В макетах нет характеристик классов, срока VIP, истории матчей или иных не передаваемых клиенту данных. Числа на примере профиля взяты из приложенного скриншота; в реализации это динамические значения.

## Общая сетка и слои

Нормальный корпус: `380×220`. Вариант корпуса берётся из существующих `tablet.png`, `tablet_epic.png`, `tablet_legend.png` по `tabletAppearanceTier`. Внутренняя область: `(88,8,286,204)`; навигация `(12,14,72,192)`; заголовок `(94,14,184,26)`; RTP `(286,16,78,20)`; основное содержимое `(94,46,274,150)`; строка состояния `(94,199,274,11)`. Карточки, текст и элементы ввода находятся на целочисленной сетке. Основная линия границы — 1 px.

Порядок от дальнего слоя к ближнему:

1. Затемнение игрового мира.
2. Одна из трёх существующих текстур корпуса `380×220`.
3. Тёмная внутренняя поверхность `(88,8,286,204)` и линии разделителей.
4. Навигация, заголовок, содержимое, scrollbar, RTP, строка состояния.
5. Hover tooltip и причина недоступности.
6. Затемнение модального состояния, диалог, его текст и кнопки; родительские элементы в этот момент не получают ввод.

Исходная текстура корпуса — самостоятельный слой. Ни один экран не является сведённым изображением.

RTP остаётся во всех разделах. Кнопка активна только во время игры, пока RTP не использован и пока режим Хаос не требует сначала выбрать класс. Причина недоступности отображается в tooltip/narration; повторного сетевого действия не происходит.

## Компоненты и состояния

На странице `02 · Components` находятся самостоятельные наборы вариантов: Button / Primary `96×24`, Button / Danger `96×24`, Navigation Item `72×28`, Class Card `130×40`, Shop / VIP Card `130×34`, Text Field `190×20`, Clan List Row `264×22`, Scrollbar `6×92`, Color Swatch `18×18`; Dialog `260×136`. Отдельно находятся 10 редактируемых векторных компонентов `TT / Icon / …` размером `12×12`, каждый с настройкой экспорта SVG. Изображения классов остаются исходными PNG-ассетами мода и подменяются на уровне экземпляра карточки.

У интерактивных компонентов есть варианты `default`, `hover`, `focus`, `pressed`, `selected`, `selectedFocus`, `disabled`, `pending` (ожидание сервера). `selectedFocus` сохраняет заливку выбора и добавляет 2 px контур focus; один цвет не служит единственным признаком состояния. `disabled` показывает приглушённый элемент, а под ним резервируется строка причины высотой 12 px или полный tooltip, если места не хватает. `pending` блокирует повторную отправку и показывает отдельную подпись; успех и синхронизация показываются только после авторитетного ответа/обновления состояния сервера. Если для действия нет отдельного подтверждающего пакета, не показывать вымышленное сообщение об успехе.

Сочетания состояний: hover не стирает selected; focus поверх selected всегда видим; disabled имеет приоритет над hover/pressed; pending имеет приоритет над повторным pressed. Названия и статусы в карточках — отдельные редактируемые текстовые слои. Полный текст сохраняется для tooltip и narration.

## Переполнение и клавиатура

- Одна строка: вычислить доступную ширину через `Minecraft Font.width`; обрезать на границе символа и добавить `…` внутри выделенной ширины. Полная строка — в hover tooltip и narration. Не уменьшать шрифт дробным scale.
- Две строки в диалоге/пояснении: разбить по словам через `font.split` и клиппировать scissor-область; если больше строк, скроллить тело диалога, оставляя обе кнопки на месте.
- При переполнении сетки карточек прокрутка идёт целыми строками, focus автоматически открывает строку. При прокрутке мышью только область под курсором меняет свой offset.
- Tab/Shift+Tab идут по видимым и доступным элементам. Стрелки перемещаются по текущей сетке/списку. Enter/Space активирует выбранный элемент; Escape возвращает в предыдущий уровень, диалог возвращает прежний focus.

## Узкий логический экран

При `width < 380` или `height < 220` не масштабировать корпус дробно. Показать компактный режим без фоновой текстуры корпуса; сохранить цвет/угловые детали терминала и все действия. Для примера `320×180`: рабочая поверхность `(0,0,320,180)`, заголовок `(8,6,304,14)`, горизонтальная навигация `(8,24,304,20)`, содержимое `(8,48,304,116)`, footer `(8,168,304,10)`. Кнопки навигации по `58×20`, gap 3; при недостатке ширины навигация прокручивается горизонтально. Карточки становятся одноколоночными, шириной `contentWidth-6`; scrollbar справа. Диалог: `min(260,width-16) × min(136,height-16)`, тело прокручивается, действия всегда видны. Для экранов ниже `240×160` сохранять 1:1 размеры целей ввода и использовать вертикальную прокрутку содержимого вместо дробного scale. Это **требуемое поведение редизайна**; текущий `TabletScreen.panelX/panelY` только прижимает корпус к нулю и может обрезать его.
